# Decision Tagger

System-1 意思決定モデル（Jev 等）を搭載した Obsidian 向け高精度スマートタグ分類プラグイン。マルチキー並列処理による超高速分類に対応しています。

[English](README.md) · [简体中文](README_zh.md) · [日本語](README_ja.md) · [GitHub Releases](https://github.com/xinye1017/obsidian-decision-tagger/releases)

---

**Decision Tagger** は、設定したカスタム判定ルールに基づいて、保管庫（Vault）内のノートを高精度に自動分類・タグ付けする Obsidian プラグインです。現在開いているノートへの即時タグ提案、特定フォルダーや保管庫全体のバッチ分類、複数 API キーによる並列処理アクセラレーションをサポートし、大量のノートを短時間でスマートに整理できます。

---

## 主な機能

- **フォルダー指定または保管庫全体の柔軟なバッチ分類**
  - **特定フォルダーの絞り込み分類**：保管庫全体の一括処理だけでなく、`Inbox/`、`Projects/`、`Readings/` など特定のフォルダーおよびそのサブフォルダーに限定して分類を実行可能。
  - **フォルダー階層ごとのノート数リアルタイム表示**：フォルダー選択ツールが階層ごとのノート数を即座に計算・表示し、処理対象の規模を直感的に把握可能。
  - サブフォルダーを安全に再帰処理し、テンプレートや Markdown 以外の不要ファイルを自動除外します。

- **マルチキー並列処理による高速分類**
  - プロバイダーに複数の API キーを登録することで、最大 8 スレッドの Worker を並行起動し、スキャン時間を劇的に短縮。
  - **インフライトリクエストの負荷分散（In-flight load balancing）**：各キーの処理中リクエスト数をリアルタイムで監視し、負荷の最も低いキーへタスクを自動ルーティング。
  - **自動フェイルオーバー＆クールダウン**：`429`（レートリミット）を検知したキーは一時的にクールダウンへ移行し、次のキーへ即座に自動切り替え。クールダウン完了後に自動復帰します。無効なキー（`401`/`402`/`403`）は自動で除外されます。

- **バッチ進捗のリアルタイム可視化と安全な中断**
  - ノート読み込み、モデル推論、タグ書き込みの進捗バー、完了率、経過時間、推定残り時間をリアルタイム表示。
  - 並列実行中は、現在処理中のノート名や並列スレッド数をヘッダーに可視化。
  - 直近 100 件の処理ログをスクロール表示（新規追加・変更なし・エラーを色分け表示）。
  - いつでも「分類を停止」可能。実行中の処理を安全に中断し、ノートの破損や中途半端なデータ書き込みを防止します。

- **単一ノートのインタラクティブな即時タグ提案**
  - 現在のアクティブノートや右クリックのコンテキストメニューからワンクリックでタグ提案を表示。
  - 信頼度しきい値を超えた「推奨タグ」とその他の候補タグを明瞭に分類表示。
  - 個別に追加するか、推奨タグをワンクリックで一括適用可能。

- **タグ判定ルールライブラリと保管庫全体の同期**
  - 保管庫内の既存タグをワンクリックでルールライブラリへ自動インポート。
  - タグごとに質問文、合致条件（Match Criteria）、除外条件（Other Criteria）を自由にカスタマイズ。
  - **保管庫全体のリネーム・一括削除**：設定画面でタグ名を変更または削除した際、保管庫内の全ノートのタグ（本文中のインラインタグも含む）を連動して自動更新・整理。

- **安全で非破壊的なフロントマター書き込み**
  - Obsidian 公式の `processFrontMatter` API を利用してタグを追加。
  - 既存の YAML プロパティ、本文フォーマット、改行を完全に維持し、タグの重複を防ぎます。

- **快適な操作性と画面内リフレッシュ**
  - 設定画面で言語やプロバイダーの切り替え、ルールの保存・削除を行ってもスクロール位置を保持。
  - API キーはカンマ区切り・改行区切りの直接入力に加え、クリップボードから 1 行ずつ一括インポートできる管理パネルを搭載。
  - Obsidian のダーク/ライトテーマに完全対応。日本語・英語・簡体字中国語を完備。

## インストール

### 方法 1: Release から手動インストール
1. [GitHub Releases](https://github.com/xinye1017/obsidian-decision-tagger/releases) から最新の `main.js`、`manifest.json`、`styles.css` をダウンロードします。
2. 保管庫のプラグインディレクトリ内にフォルダーを作成します: `<Vault>/.obsidian/plugins/decision-tagger/`
3. ダウンロードした 3 つのファイルをそのフォルダー内に配置します。
4. Obsidian を開き、**設定 → コミュニティプラグイン** で **Decision Tagger** を有効化します。

### 方法 2: ソースコードからビルド
```sh
git clone https://github.com/xinye1017/obsidian-decision-tagger.git
cd obsidian-decision-tagger
npm install
npm run build
```

## 設定ガイド

Obsidian の **設定 → Decision Tagger** を開きます:

1. **モデルプロバイダー (Model Provider)**:
   - **TypeSafe**: ビルトイン Base URL `https://api.typesafe.ai/v1/systemone`（デフォルトモデル: `jev-latest`）。
   - **OpenRouter**: ビルトイン Base URL `https://openrouter.ai/api/alpha/decisions`（デフォルトモデル: `respan/span-01-lite:free`、または任意の決定モデル ID）。
2. **API キーとアカウントプール**:
   - 利用するプロバイダーの API キーを入力します。
   - 複数キーを登録して並列処理を有効にする場合は、カンマ区切り（`key1, key2`）で入力するか、**一括インポート** をクリックしてクリップボードから 1 行ずつ貼り付けて登録します。
3. **信頼度しきい値 (Confidence Threshold)**:
   - スライダーを動かして、タグを自動適用するための最小確率を設定します（デフォルト: 70%）。
4. **タグルールライブラリ**:
   - **保管庫のタグをスキャン** をクリックして既存のタグをインポートします。
   - **新規タグ作成** または編集アイコンをクリックして、各タグの判定プロンプトと基準を調整します。

## 動作原理

1. **ノートコンテキストの抽出**: ノートのタイトル、主要な見出し（上位 8 件）、本文の冒頭 450 文字、長文ノートの末尾 260 文字を抽出します（短いノートにはフォルダーの文脈も含めます）。既存のフロントマターや本文中のタグは、モデルの判断にバイアスを与えないよう自動で除去されます。
2. **System-1 決定アーキテクチャ**: クリーニングされたノートコンテキストと有効な判定ルールを、プロンプトインジェクションの心配がない純粋な構造化データとして決定エンドポイントへ送信します。
3. **スコアリングと安全な書き込み**: 決定モデルが各タグの合致確率を算出します。設定したしきい値以上のタグのみが、原子的なフロントマター処理によって安全にノートへ書き込まれます。
